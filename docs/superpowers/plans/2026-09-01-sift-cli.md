# sift CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `sift`, a Rust CLI that reduces observability-platform output (aggregate/top-N/histogram/baseline-diff) before it reaches an LLM's context, shipped as a Nix package at `pkgs/sift/`.

**Architecture:** One binary crate. A generic `Event` model (timestamp + labels + optional numeric value + optional log body) is the common currency both platform parsers produce and the reduction engine consumes — so the reduction engine is written and tested once, platform-agnostic. Each platform module separates "fetch bytes over HTTP" from "parse bytes into `Vec<Event>`," so the parse logic (the part with real branching/failure modes) is unit-testable against fixture JSON with no network access, while the fetch function itself is thin enough not to need its own tests.

**Tech Stack:** Rust (2021 edition), `clap` (CLI parsing), `reqwest` blocking client (HTTP), `serde`/`serde_json` (parsing), `chrono` (timestamps), `humantime` (duration flags like `--bucket 5m`), `thiserror` (error enums), `tracing` (this tool's own structured logging, per `programming/observability.md` applied to itself). Packaged via `rustPlatform.buildRustPackage`, matching the existing local-source pattern at `pkgs/minecraft-modpack-tools/find-mod-bumps`.

## Global Constraints

- Design source of truth: `docs/superpowers/specs/2026-09-01-observability-skill-design.md`'s "`pkgs/sift` — token-efficient analysis tooling" section.
- **MVP scope is Loki (logs) + Mimir/Prometheus (metrics) only** — `sift lgtm logs` and `sift lgtm metrics`. Datadog, Tempo/traces, and Grafana dashboard-API support are explicitly deferred to a follow-up plan (see the end of this document) so this plan ships one coherent, working, testable tool rather than a partially-wired platform matrix.
- `rust.md`'s guard rails apply in full: `[lints.clippy]` deny table for `unwrap_used`, `expect_used`, `unwrap_in_result`, `panic`, `indexing_slicing`, `arithmetic_side_effects`, `unreachable`, `todo`, `unimplemented`, `get_unwrap` — added in Task 1, never relaxed later in this plan. Any arithmetic that needs a scoped `#[allow(clippy::arithmetic_side_effects)]` carries a `//` comment explaining why it's actually safe, per `rust.md`.
- `rust.md`'s error-handling rule applies: **one error enum per fallible function, one variant per failure site.** Each platform parser's error enum has a distinct variant per thing that can go wrong parsing that platform's response — never a single catch-all `Io(...)`-style variant.
- No `unwrap()`/`expect()` outside `#[cfg(test)]` modules, per `rust.md`.
- `--mode raw` is never the default for any query subcommand (design doc's explicit requirement) — every `QueryArgs` struct defaults `mode` to `Aggregate`.
- Auth/config read from environment variables, never hardcoded (design doc's Non-goals; `security.md`).
- `just build ali-desktop` must succeed (which runs `cargo build` + `cargo test` via `doCheck = true`) after every task that touches `pkgs/sift/`.
- Commit atomically per task. Run from `/home/ali/git/personal/nix-config` (or the current worktree); `git status` before any destructive git command.

pub fn topn(events: &[Event], group_by: &str, n: usize) -> TopNResult {
    let mut counts: BTreeMap<String, usize> = BTreeMap::new();
    for event in events {
        let key = event
            .labels
            .get(group_by)
            .cloned()
            .unwrap_or_else(|| "<missing>".to_string());
        *counts.entry(key).or_insert(0) += 1;
    }
    let total = events.len();

    let mut entries: Vec<TopNEntry> = counts
        .into_iter()
        .map(|(key, count)| TopNEntry { key, count })
        .collect();
    entries.sort_by(|a, b| b.count.cmp(&a.count).then_with(|| a.key.cmp(&b.key)));
    entries.truncate(n);

    TopNResult { entries, total }
}
```

pub fn histogram(events: &[Event], bucket: Duration) -> HistogramResult {
    let bucket_seconds = bucket.as_secs().max(1) as i64;
    let mut counts: BTreeMap<i64, usize> = BTreeMap::new();

    for event in events {
        #[allow(clippy::arithmetic_side_effects)] // timestamp() is a real calendar second count, far below i64::MAX for any event this tool will ever see; bucket_seconds is >= 1 by construction above.
        let bucket_index = event.timestamp.timestamp() / bucket_seconds;
        *counts.entry(bucket_index).or_insert(0) += 1;
    }

    let buckets = counts
        .into_iter()
        .map(|(bucket_index, count)| {
            #[allow(clippy::arithmetic_side_effects)] // same bound as above: bucket_index * bucket_seconds stays far below i64::MAX.
            let bucket_start_secs = bucket_index * bucket_seconds;
            HistogramBucket {
                bucket_start: Utc
                    .timestamp_opt(bucket_start_secs, 0)
                    .single()
                    .unwrap_or_else(Utc::now),
                count,
            }
        })
        .collect();

    HistogramResult { buckets }
}
```

```rust
pub fn diff(baseline: &[Event], current: &[Event], group_by: &str) -> DiffResult {
    let count_by = |events: &[Event]| -> BTreeMap<String, usize> {
        let mut counts = BTreeMap::new();
        for event in events {
            let key = event
                .labels
                .get(group_by)
                .cloned()
                .unwrap_or_else(|| "<missing>".to_string());
            *counts.entry(key).or_insert(0) += 1;
        }
        counts
    };

    let baseline_counts = count_by(baseline);
    let current_counts = count_by(current);

    let mut keys: Vec<&String> = baseline_counts
        .keys()
        .chain(current_counts.keys())
        .collect();
    keys.sort();
    keys.dedup();

    let entries = keys
        .into_iter()
        .filter_map(|key| {
            let baseline_count = baseline_counts.get(key).copied().unwrap_or(0);
            let current_count = current_counts.get(key).copied().unwrap_or(0);
            if baseline_count == current_count {
                return None;
            }

fn run_loki(args: &QueryArgs) -> Result<(), String> {
    let since = humantime::parse_duration(&args.since)
        .map_err(|e| format!("invalid --since {:?}: {e}", args.since))?;
    let now = Utc::now();
    let start = now - chrono::Duration::from_std(since).map_err(|e| e.to_string())?;

    #[allow(clippy::arithmetic_side_effects)] // Unix timestamps in seconds, multiplied by 1e9 to get nanoseconds, stay far below i64::MAX for any date this tool will run against.
    let start_ns = start.timestamp() * 1_000_000_000;
    #[allow(clippy::arithmetic_side_effects)] // same bound as above.
    let end_ns = now.timestamp() * 1_000_000_000;

    info!(query = %args.query, url = %args.url, "querying Loki");
    let events = platform::loki::fetch(&args.url, &args.query, start_ns, end_ns, args.limit)
        .map_err(|e| e.to_string())?;

    emit(&events, args)
}

fn run_prometheus(args: &QueryArgs) -> Result<(), String> {
    let since = humantime::parse_duration(&args.since)
        .map_err(|e| format!("invalid --since {:?}: {e}", args.since))?;
    let now = Utc::now();
    let start = now - chrono::Duration::from_std(since).map_err(|e| e.to_string())?;

    info!(query = %args.query, url = %args.url, "querying Prometheus/Mimir");
    let events = platform::prometheus::fetch(&args.url, &args.query, start.timestamp(), now.timestamp(), 60)
        .map_err(|e| e.to_string())?;

    emit(&events, args)
}

fn emit(events: &[Event], args: &QueryArgs) -> Result<(), String> {
    match args.mode {
        Mode::Aggregate => {
            let result = reduce::aggregate(events, &args.group_by);
            print_result(&result, &args.format)
        }
        Mode::Topn => {
            let result = reduce::topn(events, &args.group_by, args.top);
            print_result(&result, &args.format)
        }
        Mode::Histogram => {
            let bucket = reduce::parse_bucket_duration(&args.bucket)
                .map_err(|e| e.to_string())?;
            let result = reduce::histogram(events, bucket);
            print_result(&result, &args.format)
        }
        Mode::Diff => {
            // The baseline window is the same duration as --since,
            // ending where the current window begins.
            Err("diff mode requires a second query for the baseline window; not yet wired into the CLI — see the reduce::diff function for the underlying logic".to_string())
        }
        Mode::Raw => {
            for event in events.iter().take(args.limit) {
                match &event.body {
                    Some(body) => println!("{} {}", event.timestamp, body),
                    None => println!("{} {:?}", event.timestamp, event.value),
                }
            }
            Ok(())
        }
    }
}

fn print_result<T: serde::Serialize + ToTable>(result: &T, format: &Format) -> Result<(), String> {
    match format {
        Format::Json => {
            let json = output::format_json(result).map_err(|e| e.to_string())?;
            println!("{json}");
        }
        Format::Table => {
            print!("{}", result.to_table());
        }
    }
    Ok(())
}
```

## Fast-follow (explicitly not in this plan)

- **Datadog support** (`sift datadog logs`/`metrics`/`traces`): needs its
  own client module following the same fetch/parse-split pattern as
  Loki/Prometheus here, against Datadog's Logs Search API v2 and Metrics
  API v1 — different auth (API key + application key headers) and
  response shape from either LGTM client, worth its own plan.
- **Tempo/TraceQL support** (`sift lgtm traces`, `sift datadog traces`):
  trace data has a different shape from a log line or a metric sample
  (a tree of spans, not a flat event) — the `Event` model from Task 2
  may need a variant or a parallel `Span` type rather than a forced fit;
  worth deciding in its own design pass rather than bending this plan's
  model to fit late.
- **`diff` mode CLI wiring**: `reduce::diff` (Task 6) is fully
  implemented and tested; what's missing is `main.rs` accepting two
  query windows (current + baseline) instead of one and calling it —
  a CLI-args design decision (two `--since`-style flags? a single
  `--baseline` duration subtracted from `--since`?) deliberately left
  open rather than guessed at here.
- **Grafana dashboard/API support**: reading and writing dashboard JSON
  via the Grafana HTTP API, per the design doc's `platforms/grafana-lgtm.md`
  content plan — no query/reduction engine involvement, a different
  shape of work (CRUD over dashboard JSON, not query-and-reduce).
