# Testing generated classes on a desktop JVM

Pharos: `crates/pharos-classgen/jvm-check/` (`run.sh`, `Check.java`,
`stubs/`). It catches signature, verifier and export mistakes in seconds,
without a phone.

## What it does

`run.sh` needs a JDK and cargo. It prints `ALL PASS` on success.

1. Builds the JNI library as a cargo example with a test catalogue feature
   (a fixture library instead of a real server). The crate links its
   exports through `link()` as the app does.
2. **Export check.** Greps every `Java_...` name in the Rust source and
   compares with `nm -D --defined-only` on the built `.so`. Missing ones
   fail the run. Reason: the JVM resolves a native on its first call, so a
   dropped export would otherwise pass `-Xverify`.
3. Runs classgen with `--lib <example lib>`.
4. `javac` compiles `stubs/` (stand-in `android.*` classes: test
   scaffolding, never shipped) and `Check.java`.
5. Runs `java -Xverify:all -Djava.library.path=<dir> -cp stubs:gen:main Check`.
6. **Log contract.** Greps the captured stderr for fixed decision lines
   (notification, becoming-noisy, resume). A reworded or dropped line fails.
   Reason: a logcat query on a phone depends on those lines.

## What Check.java asserts

It prints `PASS`/`FAIL` per expectation. Examples from Pharos:

- Service `onGetRoot` returns a root whose extras carry the search flag,
  the compat Messenger binder and service version 1.
- A `MSG_SEARCH` sent to that Messenger gets an `IResultReceiver.send`
  reply with `RESULT_OK` and a `search_results` bundle whose items parcel
  under the androidx `MediaItem` class name.
- `onCreate` runs the framework's `onCreate` first, then Rust sets the
  session token.
- Browse results are sent off the main thread (`detach`).
- The art provider serves cached images read-only and refuses bad paths
  and write modes.
- Audio focus: media attributes set before the source, ducking, transient
  loss pauses, regain resumes, permanent loss releases focus.
- Foreground state, notification channel (`playback`, low importance),
  becoming-noisy pause, resume positions, `onError` and completion.

## Stubs

`stubs/android/{app,content,database,media,net,os,service}` plus `R.java`.
Write only the members the checks touch. A stub that is too permissive
hides a real signature error, so keep descriptors identical to the
framework's.

## Run

```bash
bash crates/pharos-classgen/jvm-check/run.sh
```

Needs `javac`, `java`, `cargo`, `nm`. Probe with `command -v`.

## Limits

- It proves the generated bytecode verifies, the exports exist by name,
  and the paths it exercises link and run. JNI resolves a short name
  without the signature, so a native whose Rust argument types are wrong
  is caught only on a path the check calls.
- It does not prove the real framework behaves the same. Always follow with
  a device or DHU run ([testing-dhu.md](testing-dhu.md)).
